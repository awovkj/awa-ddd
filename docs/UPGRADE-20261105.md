# 2.0.2 优化包：计划可诊断性、批量求值、报告分层与 actor 去重

本次将优化方案中的计划可诊断性、批量求值、actor 去重、报告分层、非 JSON 基线和 sqlmap 多 family 输入集中落地，不改变 exhaustion-only 最终门禁，也不放宽任何目标请求、身份、资源或写授权约束。

## 已实现

### 1. `plan.next compact` 紧凑队列

`plan.next` 新增 `compact:boolean`（默认 `false`）。紧凑模式仅返回：

- continuation 与 ready/review/blocked 计数；
- 最多 `limit` 条工作项的 `obligation_id / operation_id / queue_status / test_family / suggested_action / missing_prerequisites / evidence_ids` 等执行所需字段；
- 最多 5 条 review followups 摘要；
- 不再重复输出 `security_coverage`、`parameter_coverage`、`completion` 等大块矩阵。

适合在长会话中快速取下一批具体任务，需要完整矩阵时仍使用非 compact 模式或 `plan.audit`。

### 2. `plan.why` 单条义务诊断

新增只读动作 `plan.why {obligation_id}`，离线返回：

- 当前 queue/status、reason_code、missing_prerequisites；
- 精确 next_action 与 input_template；
- 最多 3 个 preparation_actions、4 个 evidence_ids；
- 不发送请求、不创建 decision。

用于替代“反复 inspect 同一个不可执行条目”的队列空转。

### 3. `assessment.batch` 显式批量求值

新增 `assessment.batch {items:[{obligation_id,evidence_ids,oracle}]}`：

- 最多 50 条；
- 每条完全复用单条 `assessment.evaluate` 的参数、证据、身份、资源和 oracle 门禁；
- 逐条返回 accepted/error 与恢复提示；
- 单条失败不会中止后续条目，但绝不重试或补造断言；
- 返回 `evaluated / failed / requests_sent` 汇总。

### 4. `coverage_policy=subject` actor 去重

项目新增配置 `coverage_policy: "subject"`（`project.create`/`project.update`，新项目默认 `subject`；可显式回退 `legacy`）：

- 按真实账号 `subject` 合并重复 ledger actor（如 `alice` / `alice-r0` / `alice-n`）；
- 仅有未知空 tenant 的别名会并入唯一已知 tenant；多 tenant 时仍保持隔离；
- 优先选择已有身份核验 session 的 actor 作为代表；
- 仅影响后续 `build_plan`，历史 actor/证据/义务不删除；旧义务保留为 superseded 历史。

该配置解决“同一真实账号反复创建 actor 导致 baseline/access 义务成倍膨胀”的问题。

### 5. 浏览器动作兼容修复

`browser.visit`：

- 已接受 `action` 作为 `type` 的兼容别名：`{"action":"fill","selector":"#q","text":"..."}` 不再被静默当成 click；
- `fill` 同时接受 `text` 与 `value`；
- `wait` 继续使用 `ms`；
- 新增 `waitForDialog` 动作，可等待并记录应用触发的真实 dialog；
- `contracts.py` 与 `src/tool-guidance.mjs` 已同步精确 schema 文档。

### 6. 报告分层 profile

`report.build` 新增 `profile: full/technical | executive | both | repro`：

- `full` / `technical`：现有完整技术报告与复现包；
- `executive`：输出 1-2 页决策摘要，省略大体积 reproduction 附录；
- `both`：同时生成 `report.md` 与 `executive.md`；
- `repro`：保留复现实体和请求包，便于单独交付。

### 7. 非 JSON 基线

`assessment.evaluate` 的 baseline 支持静态文本/二进制响应：

- `selector:"@raw"` + `expected_text`；
- 或 `selector:"@raw"` + `expected_sha256`；
- 仅用于正常基线记录，不是漏洞证明，也不改变 `baseline` 的阴性边界语义。

### 8. sqlmap 多 family 输入

`tool.sqlmap` 支持在同一注册输入同时声明 `sql_injection` 与其他 family（例如 XSS）时，按精确 `input_selector` 选择 SQL 分支；新增可选 `test_family` 只接受 `sql_injection`，不会扩大工具参数或自动执行 scanner。

## 测试

- `coverage_policy=subject` 对重复 subject 的折叠；

- `assessment.batch` 单项失败不影响后续，错误码保留；
- 浏览器 `action` 别名、`text` 字段和 `waitForDialog`；

完整回归：

- Python：1497 tests，OK（1 skipped）
- Node：214 tests，全部通过
- 25 KB prompt budget 仍满足

## 未改变

- `plan.finalize` 仍只接受严格 `reason:completed`；
- 任何目标请求仍受 scope/identity/resource/write 门禁；
- `assessment.batch` 不等于自动 coverage 完成，也不允许跳过控制；
- 历史证据与 finding 生命周期保持不可删除。
