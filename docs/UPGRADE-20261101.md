## 核实的根因

### 1. 参数登记不等于参数实验

第一轮携带了 `order_time` 等字段，但没有针对字段构造同身份、同 fixture、其他输入不变的变体与对照。原队列虽有独立 input/family 义务，却缺乏紧凑的参数级观察矩阵，容易让接口基线、未知消费点与重复观察淹没未测字段。

新增矩阵按 `(operation, location, selector, schema_branch, family)` 投影。它区分：

- `unobserved`：没有可归因的当前捕获；
- `needs_controls`：携带了字段，但没有同上下文目标变体；
- `observed_unassessed`：存在候选输入变体，仍未通过判据；
- `consumer_review`：消费点未知，不能变成已测；
- `observation_limited`：分支不明确或派生解析预算受限；
- `tested`：当前 typed decision 有效，不只是历史标签。

明确 SQL/HTML 消费点要求的族也进入矩阵；只登记 generic 不会显示“该参数全部族已测”。正常、变体与敏感度三值只形成候选对照，不自动求值或关闭义务。

### 2. multipart 失败发生得太晚，且文件名不是内容

实际失败材料以 `EF BB BF` 开始，然后直接接 multipart 首 delimiter；这是 PowerShell `Encoding.UTF8` 写文件产生的 BOM，不是 LF/CRLF 混用。旧执行侧与判据侧使用不同解析器，导致已发出的工件直到求值阶段才暴露 framing 不一致。

执行、fixture 绑定与判据现在共用严格原字节解析器。BOM 在 `http.preflight` 就返回 `multipart_framing`、`framing_issue:utf8_bom`、`repair:rewrite_utf8_without_bom`，不静默修改正文、不自动重发。合法 CRLF preamble/epilogue 保留原字节，重复字段/头/参数、歧义编码和 framing 注入仍拒绝。

文件内容使用 `file` 或精确 `<part>.content`；文件名使用明确声明的 `file.filename` 或 `<part>.filename`。单文件别名只有无歧义时可用。测试文件名时，把 fixture 绑定到**不变的自有内容**，不能同时改变 filename/content，或修改 fixture 来伪造同资源对照。合法 boundary 值变化可以规范化，非目标内容、头和顺序不能随之改变。

规范化只作用于严格解析分支生成的内部上下文及实际媒体类型；业务 JSON 即使伪造 `format`、`control_parts`、`prefix_base64` 等字段也没有该权限。旧不安全判据重新校验后不能继续关闭义务，原记录不改写。

对话中的若干 XXE/上传对照还同时修改文件名、内容、price/stock 等字段，不能因 framing 修复而追认为有效实验。

### 3. 判据帮助缺少 discriminator 的精确契约

`action.help name:assessment.evaluate` 现在返回 8 种既有 `oracle_contracts` 的字段、控制顺序、约束与占位符示例。特别明确 typed extraction 除 `expect` 外还需要 `expected_value`、`source_reference`；state readback、SQL metadata 和 error channel 各自使用不同字段。

判据错误附带本地 help/evidence/run 恢复指针；不把“输入形状错误”当成重新发包许可。`analyst_runtime` 仍走真实 `finding.record` XSS 入口，不是新增的 evaluate discriminator。

### 4. 收尾错误未指出真正失败的族

当前旧代码的 `planned` 集合已包含完成与未完成的 active input/access/ownership 测试，并未过滤已求值的反序列化义务。只读台账显示 `deserialization` 的当前义务已求值；缺少的是 `generic` 安全测试，generic 记录实际是 `input_review`。

对话第 2233 行在反序列化阴性完成前已经出现相同 all-planned 错误；第 4997 行再次失败，第 5002 行把 deserialization 改为 N/A 才引入“不能排除既有测试”错误。因而“已完成族没有合法状态导致死锁”并非这次的真实根因。

错误现在明确返回失败族和下一步核对入口。同时提供显式 `completed` 状态，要求非空、当前有效、全部已求值的族义务，并绑定真正 decision/工件；这是可读性升级，不是关闭未测族的捷径。旧 `planned` 契约与严格两轮 exhaustion gate 保留。

### 5. 低熵提交字段污染整份报告

历史报告将单字符密码提交候选 `x` 作为全局子串秘密，污染 `xxe`、`external_id`、fixture 和复现代码。HTTP 失败不能证明密码无效，修复不作这种推断。

短提交候选按已捕获来源和敏感字段位置脱敏；关联响应/证明使用局部保护，不污染整份报告类别与代码。实际会话头、浏览器 fill、成功提交及响应泄露的真实秘密继续优先进入全局保护，哪怕只有一两位。同值被识别为实际秘密时，提升为全局保护；原始工件留私有。

## 新的发现与调度能力

`coverage_first` 优先从未观察/从未变化的输入，保留跨族、跨操作轮转，以及新参数与已有材料复核的公平插槽。行政 review 和真实受阻项不被删除；基线和重复发包不能制造完成度。

`preparation_actions` 给出范围、主体、fixture、既有工件等具体的离线准备入口。验证码/SMS/token 输入另有 `session_continuity`，提醒维护同源匿名 Cookie jar 或核验会话，分别测试各因子及生命周期；不自动转发 Cookie、不根据“抽奖次数为零”猜测必须充值或付款。

JS AST 离线发现 `innerHTML`、`insertAdjacentHTML` 和 `location.href/assign/replace`，记录精确行列、引用字段与同 bundle 的可能输入绑定。字段同名不等于 taint 证明，重名和跨 bundle 情况保持不确定；不执行源代码、不导出源码片段或请求值、不自动声明 consumer。

`assessment_hints` 支持本次实际定义形状：

```json
{"version":"fixture-v1","maxScore":1,"vulns":[["/api/example",[["keyword","GET"]],"SQL注入",1]]}
```

也支持 [标准化导出示例](../examples/assessment-hints.json)。仅生成 `answer_key_hint` / `validator_hint` / `assessment_hint`；定义位置、validator 结果和来源用于选题，不用于确认、否定或授权。原生定义没有 HTTP method，不能从 GET/POST/FILES 参数位置猜方法。

本版不增加自动 Actuator/heapdump 探测、评分接口调用、XXE/JAR 读取或通用扫描入口。只有调用者明确提供的离线材料进入上述适配器。

## 使用与恢复

```json
{"action":"plan.next","project_id":"assessment","input":{"limit":5,"parameter_status":"untested","parameter_offset":0,"parameter_limit":10}}
```

`parameter_coverage` 有独立 `offset/next_offset`，不与主队列或 checklist 游标混用。超过 24 KiB 的展示保留完整安全计数，并为参数页给出当前 `parameter_offset` 的重读模板；先恢复省略项，再跟随该页正式游标。

```json
{"action":"action.help","input":{"name":"assessment.evaluate"}}
```

```json
{"action":"surface.import","project_id":"assessment","input":{"format":"assessment_hints","path":"<explicit local export>","base_url":"<authorized origin>"}}
```

每次 checkpoint 的 `parameter_delta` 分开显示 `newly_tested`、`newly_observed_variants` 与重新打开的数量。首个/旧 checkpoint 只建立比较基准，不伪造新增进展。内部仅保存参数身份 key，不保存或公开输入值摘要；超派生预算不作增量声明。

续接已补齐预算受限后的 typed/variant 分轴比较、已有候选对照的离线复核、评估提示的显式证明绑定、AST 作用域和提取包验收；最终回归与新安装包记录见 [20261102 续接闭环](UPGRADE-20261102.md)。旧投影的安全 typed 比较可保留，旧变体必须重新建立完备基准。

参数观察派生最多 50000 次输入 view、累计 64 MiB 输入解析预算；超限显式标为受限，不删除工件或影响已有有效判据。单次 next/audit 复用当前 inventory，不做跨调用缓存。

## 保留的安全边界

- restricted 角色缺失继续受阻；匿名 401/登录 200 不能自证服务端角色权限。
- SQL 布尔/时间信号与 `sqlmap no_injection` 不变成通用阴性或 metadata 确认；缺通道保留未决。
- 语义阴性仍要求正常/变体/敏感度对照；一个失败因子不能否定整条认证链。
- 写后状态必须有真实有序 scenario、同主体和精确 fixture/readback；ACK、评分或人工文字不能代替状态。
- 不合并所有义务为一次成功请求，不丢弃重复原始观察，不用 observation_budget 隐藏行政工作。
- scope、身份、资源血缘、不可变历史、实际浏览器运行时和 strict finalization 不放宽。

报告区分实际运行时证明、人工复核、代码提示和答案键提示。代码/答案线索不能进入运行时证实数量，草稿成功和靶场分数不能授权停止。
