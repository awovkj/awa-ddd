## 依据

本轮依据用户指定的 `D:/Backup/Downloads/dsh-session-session-45723009-37d0-4402-9a08-260034451cae/session.v4.jsonl`。该会话是使用 awa-ddd 对本地天积商城（HeaSec Mall）进行的授权靶场评估，不是设计讨论。

文件统计（只读分析）：

- 6,180 条 JSONL 记录、14,819,158 字节、16 个 turn；
- 936 次 `tool/call`、942 条 assistant 消息、118 次 compaction、42 次 LLM retry；
- 62 条 `user/message`，其中 `source.kind=user` 只有 15 条，其余为时间上下文、模型切换、技能目录和权限通知；
- 累计 321,376,825 tokens（输出 528,686 tokens）。

会话中的人类要求依次是：从 `http://127.0.0.1:8081/` 开始评估；多轮“继续”；把已挖到的漏洞提交到靶场 `/vuln`，再根据漏洞清单反推并验证；复现第二轮全部项；核查是否使用了 Yakit MCP 和 sqlmap；分析“没调用”是没必要还是没想到。本升级只读取该会话作为研究材料，不把其中的目标、账号、Cookie、payload 或历史授权当作本轮执行授权。

### 第一轮与第二轮的落差

会话自己的对比：

| 指标 | 第一轮 | 第二轮 |
|---|---:|---:|
| 注册操作 | 15 | 40 |
| 采集证据 | 22 | 100+ |
| 形成判据 | 1 | 32 |
| 登记漏洞 | 1 | 22 |

第一轮已经手工打通过 SpEL RCE、XXE、SSRF、退款、XSS、Actuator 等，却没有进入台账。原因不是“没发现”，而是：

1. `finding.record` 在 evidence/session 失效时把错误混在一起；`origin` 报错不列合法值，反复重试后跳过。
2. `sql_metadata` 只接受“数字输入 + 精确等式谓词且基线保持”，ORDER BY / LIKE 注入点无法构造区分性谓词，真实 SQLi 被系统性判成 blocked。
3. 会话默认 TTL 30 分钟，没有续期动作；多阶段取证不断重建 session，`verify_current_evidence` 把 TTL 过期当成证据失效。
4. `http.capture` 无法携带业务会话 cookie，captcha/SMS 只能退回 curl，证据链断开。
5. 未利用靶场 `/vuln` 清单反推缺口；黑盒遍历没有方法矩阵，GET 覆盖不能暴露同路径的 DELETE。

最终报告仍有 27 个 finding 因 `session_expired` 变成 `current:false`；覆盖率显示 0.2%（742 条存储义务，716 条非 superseded），其中 441 条是同一操作的多个测试 resource 与同角色 actor 相乘产生的 ownership 义务，分母失去可读性。

## 0.5.0 的修改

### 1. 会话生命周期：TTL 与证据分离

- `identity.session` 新增 `renew:true`：保留 session_id、generation、headers 和身份核验，只延长 `expires_at`；换凭据必须新建会话并重新 `identity.verify`，尝试在续期时换 headers 返回 `renew_shape`。
- 默认 TTL 从 1,800 秒提高到 7,200 秒。
- `session_valid` 只用于“即将发新请求”的检查；`verify_current_evidence` 默认允许 TTL 过期，仍强制 generation/actor 绑定和身份核验完整性。TTL 过期不再让历史证据或 finding 失效。
- `evidence.inspect` 增加 `session_status`（none/live/expired/rotated）与 `usable_for_new_requests`，把“字节完整”“策略仍匹配”“当前身份可继续发请求”拆成三个维度。

### 2. SQL 证据：三条确认通道，而不是一条独木桥

- `sql_metadata` 保留直接回显路径，同时新增 sqlmap 元数据 transcript 路径：只要 sqlmap run 完整、成功、只读、实际返回 `database()`/`current_user()`，并绑定 operation/input/session，即可确认；ORDER BY / LIKE 等常量谓词退化场景不再被迫 blocked。`negative_value` 与数值输入等式谓词改为可选加强。
- 新增 `error_channel` 判据：DBMS 报错正文携带元数据（如 extractvalue/updatexml 的 XPATH syntax error），三条证据（baseline/recovery/negative）中只有 recovery 命中命名 `(?P<value>...)`，且值不来自输入反射。
- `finding.record` 的 analyst SQL 新增 `sql_evidence{control_evidence_id,injection_evidence_id,observed_change}`：未参数化 DELETE 等 write-side/destructive 注入没有元数据可掏时，用同 operation/method/actor 的对照/注入差异确认，记为 `confirmed_scope: sql_behaviour`，不再需要改非 SQL 类目绕过。
- `is_sql_category` 识别 “Unparameterised SQL / Mass Data Destruction”等 SQL 类目，封住改类目绕过的口子。
- 机器判据和人工复核共用 `validate_confirmation`；行为型 proof 会重新校验两条证据，而不是相信 reviewer 文字。

### 3. 资源绑定与写操作

- `identity.resource` 的 body selector 支持：JSON Pointer（`/0/product_no`）、递归 JSON key、multipart 表单字段名（如 `file`）、文件 part 的 filename/content；外部 ID 与 JSON 数组按结构比较，不再按 Python repr 比较。
- 同一 resource_id 可更新 binding/state；错误信息给出 expected/actual，并提示 JSON 数组用 Pointer、multipart 用字段名。
- `http.capture` 新增 `anonymous_cookie`：只用于 public 的 captcha/SMS/cart 等匿名状态，不能与 session 混用；证据记录 `auth_mode`。
- 没有 resource-bearing input 的 self-state 写操作（如 `audit/status`）可由已核验会话的 actor 绑定，仍要求 `allow_mutation` 与 `effect:test_resource_write`；其他写操作仍必须有 resource_id。

### 4. 浏览器与 SPA 台账

- `browser.visit` 支持写请求：项目 `allow_mutation:true` 后默认允许，单次 `allow_write:false` 可保持只读；写请求只允许访问 visit 目标同源，`write_requests`/`write_authorized` 保留在观察中。
- 页面观察新增 `navigation_trail`：记录初始 URL、每个成功 action 到达的 finalUrl、最终 URL。`page.mark`/`_runtime_proof` 允许把由成功 action 到达的页面绑定为该页访问；SPA 登录跳转不再系统性误伤。
- XSS 的 dialog 绑定继续要求应用触发的 marker；若 consumer_url 是通过 action 到达的，dialog 必须发生在到达之后。

### 5. 覆盖与报告

- `build_plan` 的 ownership 义务按 operation 选一个代表 resource，并按角色去重同角色 actor；同一操作注册多个测试 fixture 不再把义务数乘以 fixture 数。
- `evaluate_coverage` 新增：
  - `coverage_by_kind`：按 obligation kind 拆 total/evaluated/open/blocked/ratio；
  - `surface_coverage`：operation/input 级 operations_tested、inputs_tested、ratio；
  - `method_coverage`：同一路径的 tested 方法与 untested_siblings（PUT/PATCH/DELETE 等）。
- 报告按严重度与攻击面分组当前 findings，历史/失效项单列 reason；增加 method coverage 表、surface coverage 指标和 gap details。`format_version` 升为 3。
- `coverage_ratio` 保留为义务加权兼容指标；可读性由 surface_coverage 与 coverage_by_kind 承担，不再用一个 0.2% 数字代表全部进度。

### 6. 错误与工具适配

- `finding.record` 先校验轻量参数：origin 报错列出 `independent | hint_guided | imported`，machine 缺 decision_id 与 analyst 缺 reviewer/reason/evidence_ids 分开提示。
- `surface.register` 接受 `https/http1` 作为 HTTP executor 别名，`auth:none/anonymous`、`ownership:none` 等常见误写归一化。
- `tool.sqlmap` 的 DBMS 大小写不敏感并支持常见别名（mysql/mariadb/postgres/mssql/sqlserver/sqlite），错误列出合法 profile；缺失参数不再被吞成 `invalid input or unavailable local resource`。
- Yakit `http_fuzzer` 的 `fuzzTagMode` 从 `close` 改为 `standard`，修复 `{{repeat(1)}}` 模板前缀留在请求行导致所有重放 400 的问题；若响应仍含未渲染模板，run 记录 `transport_warning`，不把 harness 400 当作目标响应。
