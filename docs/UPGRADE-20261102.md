## 修复的断点

### 1. 已有参数对照先离线核对

`parameter_coverage` 的 `control_candidate_evidence_ids` 给出单一当前上下文中精确输入的候选 E 引用。上下文包括 operation、主体/会话 generation、fixture、其他输入和媒体类型；不混合跨主体、跨 fixture、其它操作、损坏或不完整工件。

`plan.next` 优先 `evidence.inspect`，不再在同一输入已有足量候选时反复提示发包。三值仅是正常/变体/敏感度候选，不自动分配控制角色、不选择 oracle、不关闭义务。不同族保留两值/三值及成功响应要求；SQL 报错观察可进入待复核组，但不能被投影为 SQL 确认。XSS 控制存在时先核对，未知消费 URL 仍保持 `identify_consumer`、`invoke_now:false`；已有合格运行时继续优先真实 `finding.record` 入口。

`coverage_first` 保留新参数、已有材料、跨族及跨操作的公平插槽；行政工作、受阻事项和原始重复观察不删除。

### 2. 检查点区分两种完备性

私有 `parameter_progress` 使用 v2 分别保存 tested/variant 完备状态；公共 `parameter_delta` 增加：

- `tested_projection_complete` / `variant_projection_complete`；
- `tested_comparison_available` / `variant_comparison_available`。

超过身份 key 上限不能声明增量；观察派生预算受限或分支不明确时，不建立可比较的变体基准。恢复预算后没有新增捕获，不会凭空报告新变体。旧投影只保留可验证的 typed 比较，变体建立新基准；当前有效 typed 决定即使观察派生受限仍可离线读取，不被伪造为新的实验。

`completed` 族错误包含确切 `test_family` 与 `plan.audit` 恢复入口；空族、未求值族、失效证明和未追踪消费点仍拒绝。

### 3. 评估提示有显式、可重验的复核收口

普通 `candidate.link` 仍仅血缘。仅三类评估提示可显式绑定已有证明：

```json
{
  "action": "candidate.link",
  "project_id": "assessment",
  "input": {
    "candidate_id": "<saved hint C id>",
    "operation_id": "<registered O id>",
    "proof_decision_ids": ["<current accepted D id>"]
  }
}
```

`assessment_hint`、`answer_key_hint`、`validator_hint` 的 `assessed_hint` 回执绑定精确来源上下文、URL、方法、协议、输入、分支和族。每个提示输入/当前分支需独立兼容正向，或在源方法已明确时覆盖全部提示族的有效阴性。原生定义缺方法，不能按 GET/POST/FILES 参数位置猜方法来否定；一个 RCE 机制阴性不能排除其他机制。

评分、基线、普通人工文字、无关决定、导入回执及同名客户端 sink 均不足。复核只减少当前线索待查数量，不新增 finding/decision/evidence，不修改任何义务或覆盖分母。全部有限语义阴性仍只表示指定 observable 下的具体假设已调查，不能据此宣称答案键为假、RCE 本体不存在或整条认证链安全。提示来源仍单列 hint-only，`assessment_checklist` 也不误计为其它候选。

来源校验绑定已经导入的 candidate 快照、原 SHA-256/locator 和私有上下文，不自动监测外部 source.path 的当前字节。外部定义文件更新需要显式重新导入；新 SHA 会产生新的未决线索。当前证据或已导入上下文改变会重新打开；重连不附证明或 `candidate.reopen` 去掉当前回执。

代码 sink 没有可验证的真实 source-to-runtime 消费点绑定时仍未决；不能用同输入在另一页面的 XSS 证明关闭所有 sink。这是明确边界，不提供文字归档捷径。所有自动停测仍需要零未决及两轮当前完整 frontier。

### 4. AST 不再把局部绑定当浏览器全局

离线解析先构造词法作用域并标记写入，再提取线索。覆盖解构（嵌套/default/rest）、catch、for、switch、class 和函数/var 作用域；同名局部 `fetch`、`axios`、`window`、`location` 不注册成真实网络或全局导航。

全局或别名重新绑定、替换 Location 对象/方法后保持待复核，不能沿用过时别名伪造接口或跳转。普通 `location.href` 导航写入仍可识别；ObjectPattern 的 `innerHTML` 键不被当作渲染 sink。仍不执行 JS、不输出载荷或源码片段、不把字段同名当 taint。

### 5. 输入身份及隐私契约

登记入口校验 inputs 为有界数组、name 为非空字符串、selector 为精确字符串、schema_branch 为字符串或 null（保留旧 OpenAPI 的空分支字符串）。body/GraphQL 仍支持显式 JSON 根 selector `""` / `"$"`，不破坏已有整文档对照。原数值凭据别名回归移至合法的业务 metadata，继续断言数字秘密不会借控制计数恢复；数值/布尔不能作为分支身份。

坏类型在登记、规划、审计及 preflight 提前失败，不留下半登记，也不走到 `unhashable` 或不可绑定的矩阵。异常存量元数据 fail closed 并给出 `surface.inspect` 来源核对入口；检查器保留只读来源视图，明确 `inspection_limited/input_identity_error`，不借用历史 evaluated 状态。坏数组形状的未知计数为 null，不伪装成零输入；不静默修正历史来源或绕过实际审计错误。新增 E 引用、回执 D 引用和增量布尔值进入动作专用发布 schema；私有来源上下文和值摘要不公开。
