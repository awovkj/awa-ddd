# 2.0.1：归档、精确输入与续接收敛修复

本次升级针对 [460B14C4 会话对照审计](SESSION-20261104-460B14C4.md) 中的五项问题。默认仍使用 v1 的 10 组、63 动作；没有将已有评估切换为 v2，也没有将历史观察补写成新的成功实验。

## 已实现的行为

| 原问题 | 2.0.1 行为 |
|---|---|
| 同页第二次观察覆盖第一次归档，反复出现 orphan | 每份 page_visit 保留可验证的多页面采用关系；页面最新访问指针继续用于展示。重复采用幂等，篡改、范围变化和真实 BLOCKED 仍重新进入复核。 |
| URL 自动发现额外 null query，交接错选 default | 只有完全未声明的 query selector 才自动补输入；模板显式传 schema_branch，包括 null。旧真实分支与全部证据历史保留，可按分支分别声明。 |
| blocked/open 或行政改动被当作真实进展 | 保留原 progress_id/CS/FN，新增 semantic_progress_id。有效闭环、已验证准备和客观前提改善推进；状态往返、失败和 inconclusive 不清零停滞。 |
| 新全局 PR 再次派同一个失败任务 | 任务失败按项目、任务、证据/身份/资源/前提上下文保存。失败只允许继续取下一可行页；真实上下文变化后重新尝试。 |
| 商品名称 XSS 被绑定到搜索 keyword | 新增受控 stored_api 消费链：实际写入源、相同 fixture、JSON 内容版本回读、native 正常/攻击 viewer。搜索定位词不会被当作写入源。 |
| WSL sqlmap 存在却因错误路径没有执行 | runtime.probe 返回经本地检查的 backend/路径与 tool.probe 模板；tool_path 区分未配置、后端错误、过度转义、非绝对路径、文件缺失等。保留当前执行后端。 |

## 浏览器历史兼容

采用关系保存每份观察的摘要、来源、身份与页面关联，审计重新验证原始观察事件、文件摘要、当前范围和成功访问。既有 `page.visit_adopted` 事件可只读恢复历史关联；恢复不会写用户数据，也不会将单纯 `visited:true` 视为全部观察已复核。

两份同页观察连续采用后均保持已归档。对同一已采用观察重复调用 `page.adopt` 不移动最新指针，不新增无意义事件或语义进展。旧观察文件被篡改、来源/身份被改写、页面被排除或明确 BLOCKED 时仍重新待复核，不能通过新访问吞掉旧缺口。

## 精确分支

新登记 `...?confirm=true` 且已显式声明 `query/confirm/default` 时，不再自动添加 `query/confirm/null`。多个真实 schema 分支仍独立登记。

对于已有 default/null 两份记录，按 `plan.next` 或 `assessment.prepare` 的完整模板执行声明：`schema_branch:null` 精确选择无分支项，`schema_branch:"default"` 选择 default。省略分支且存在多项、错误分支或坏类型均原子拒绝；不会为清空任务而删除旧义务、输入或 accepted decision。

## 存储 API 到 SPA 的 XSS 证明

原直接文档证明保持既有约束。新 `finding.record` 的 `xss_consumption` 支持 POST/PUT/PATCH 写入源经过同源 GET JSON API，被不同已核验主体的 native 浏览器消费。结果仍为 analyst runtime 证明，只关闭该条明确源输入义务。

实际观察顺序必须为：

| 顺序 | 记录 | 必须验证的事实 |
|---:|---|---|
| 1 | 正常 writer capture | 已核验 writer、可回退 fixture、正常值、成功写入断言 |
| 2 | 正常 reader capture | 已核验 viewer，JSON 返回正常写入值与同一 fixture 标识 |
| 3 | 正常 native viewer visit | 原始 API 响应摘要匹配正常回读，正常业务交互不执行攻击标记 |
| 4 | 攻击 writer capture | 同 writer/fixture，只改变被测源输入，唯一标记在选中攻击值中 |
| 5 | 攻击 reader capture | 重复相同 GET 请求，JSON 返回攻击写入值与同一 fixture 标识 |
| 6 | 攻击 native viewer visit | 同 viewer、相同成功交互，实际消费文档触发唯一标记，API 响应摘要匹配攻击内容版本 |

`evidence_ids` 按角色排列为 writer-normal、writer-attack、reader-normal、reader-attack；该数组顺序与上表实际执行顺序不同。以下只展示提交形状，所有 ID、selector 与断言需来自真实台账和已检查的原始材料：

```json
{
  "mode": "analyst",
  "obligation_id": "<实际写入源的XSS义务ID>",
  "evidence_ids": ["<正常写入>", "<攻击写入>", "<正常回读>", "<攻击回读>"],
  "runtime_visit_id": "<攻击native消费观察>",
  "consumer_url": "<真实获准消费页>",
  "runtime_marker": "<实际应用触发的唯一AWA-XSS标记>",
  "xss_consumption": {
    "type": "stored_api",
    "normal_read_evidence_id": "<正常回读>",
    "attack_read_evidence_id": "<攻击回读>",
    "normal_runtime_visit_id": "<正常native消费观察>",
    "content_selector": "<实际返回内容的JSON Pointer>",
    "resource_selector": "<实际fixture标识的JSON Pointer>",
    "write_success_selector": "<实际写入成功断言的JSON Pointer>",
    "write_success_expected": true
  }
}
```

标题、分类、影响、修复、reviewer 与 reason 等既有必填项仍需提交；完整字段由 `awa_project action.help {name:"finding.record"}` 查询。准备和验证均可离线执行，不能为填账自动重放未知写入。

native 原始观察新增开始/完成时间、实际文档 URL、有界请求/响应摘要及交互原值的私有校验材料。每个 document/xhr/fetch 响应最多计算 8 MiB 摘要；超限显式缺少完整内容证明，不伪造摘要。API 内容必须与选中的完整回读字节一致；动态且无法绑定的响应仍保留未验证。旧观察没有这些材料时维持历史状态，新证明需要真实补齐，不能根据现象文本合成。

消费交互必须可比，写入源须包含实际执行唯一标记的 alert/confirm/prompt 脚本表达式。当前源到消费证明不接受 fill、输入字符或剪贴板快捷键，避免编码手填脚本成为独立来源；原正常写入和 reader 请求中的 URL、HTML、JSON 转义及 base64 标记也会检查，有界解码不足时保持未验证。浏览器仍可执行普通 fill 收集材料，填入原值只保存在私有 artifact，公开输出继续脱敏，不公开低熵填值的直接摘要。MCP 导入不能冒充带已核验身份的 native 消费链，静态 HTML、孤立弹窗或人工 evaluate(alert) 不能绕过源输入绑定。

## 续接与任务失败

`semantic_progress_id` 是新的真实进展标识，原 `progress_id` 继续描述当前工作状态，严格最终完成继续依赖原快照、当前 checkpoint、有效证据与 frontier 规则。

新进展只由有效安全闭环、已核验身份/资源准备、具体新输入、有效多观察归档或客观缺前提减少建立。同一事实切回不会再次累计。失败、行政 review、blocked/open 往返和没有结论的观察不会清零停滞。

宿主按任务及其实际上下文保存失败原因，跨全局 PR 保留。失败与成功复核分别计数；失败后继续找其他可行小页，实际材料或前提变化后才重新派发。真实取消、新用户意图、offline-only、当前页恢复和多项目隔离继续生效。

新增会话形状回放中，18 个行政 PR 状态产生初始通知和一次具体交接，共 2 次 notice，同一上下文失败只计 1 次 failed attempt。这是离线回放结果，不是重新渗透靶场的结果。完整评估仍须真实耗尽登记范围；抑制重复通知或正常轮结束不会建立最终完成权限。

## SQL 路径恢复

先读取 `runtime.probe` 的 `sqlmap_candidates`，每项包含经过检查的 backend、路径、`tool.probe` 模板及必要的 workspace 隔离提示。保持当前执行后端；Windows native 可以使用明确检查过的 WSL UNC 脚本，WSL profile 需要独立 workspace。

候选只来自固定本地位置和已验证的 WSL sqlmap 文件，不扫描全盘、不静默修写输入路径或改目标 URL。存在的文件仍需通过 `tool.probe` 实际版本检查，成功配置之后可以省略路径复用。错误输出只提供有限原因码和离线恢复模板，不回显用户传入路径或正文。

本机已真实运行只读 metadata probe 与 sqlmap `--version`，native UNC 配置可复用，取得 `1.10.8#stable`，`target_traffic_sent:false`。验证使用新建临时台账，未访问用户目标或重放历史请求。
