## 已有证据准备

在 `awa_assess` 调用，四种 target 恰选一种：

```json
{"action":"assessment.prepare","project_id":"assessment","input":{"finding_id":"<当前人工发现ID>","limit":3}}
```

也可指定 `obligation_id/evidence_id/operation_id`；可选 `evidence_ids` 为 1..25 个当前完整捕获，独立 `offset/limit` 的 limit 为 1..10，默认 3。准备返回当前义务、候选控制 ID、判据顺序及缺字段、实际消费点声明模板和已有证明复核指针。

这个入口发送零请求、创建零判定。候选顺序需要人工核对正常、攻击、敏感性或阴性角色；模板中的 oracle 不包含猜测的响应断言。未知 consumer 保留 `input_review`，具体声明后才重新规划。SQL、XSS、提取和状态链仍使用各自的严格门禁。

准备原始人工发现时只使用其支持证据；后续同值捕获不会替换原控制 ID。显式缩小证据集合后，集合外的已有证明标为 `proof_outside_selection`，不建议补发实验或替换排除的证据。以某条 evidence 为入口时，输入比较锚定其实际身份、fixture 和其他输入上下文。

授权候选同时检查真实角色与主体独立性，缺失给出 `roles_unverified/actor_independence`。状态链候选复用现有 `_scenario_observations`，要求真实完成事件、对应 scenario-owned HTTP run、预检图、顺序与时间边界及已核验身份；复制场景或并发记录不能伪装成可用顺序状态链。XSS 模板明确为 `mode:analyst`，必须另外绑定真实应用触发的运行时和具体消费页。

## 当前证明与人工发现关联

先根据实际控制填写 oracle，用 `assessment.evaluate` 取得当前 confirmed decision；再调用：

```json
{"action":"finding.bind","project_id":"assessment","input":{"finding_id":"<原人工发现ID>","decision_id":"<当前已确认判定ID>","reviewer":"复核人","reason":"依据原对照核对具体输入、作用域与影响"}}
```

绑定要求原项为当前 active analyst finding，证明属于当前已求值且未 superseded 的同一义务，类别对应已实现的具体证明族，证明证据是原支持证据的子集。原支持材料也逐项核验。普通跨操作证明拒绝；真实 `state_transition` 按其验证过的 scenario/readback 允许必要读回。重复绑定、已发布证明、坏工件、被替代判定、未知类别和人工文字证明拒绝。

成功时创建替代 finding，并在同一事务中记录旧项的 superseded 生命周期 revision。原文本、支持材料和 decision 保留，义务及源机器证明不改写；中途失败整体回滚。XSS 使用现有明确的运行时 `finding.record` 路径。只读准备和绑定都不授权重放请求。

人工 `finding.record` 也可显式引用当前真实 `proof_decision_id`，要求精确类别、证据集合及顺序；原有 SQL 元数据和错误通道支持继续受到当前性检查。人工叙述不会自动完成其他输入、漏洞族、状态或机制。

## 独立属性复核

```json
{"action":"surface.recon","project_id":"assessment","input":{"mode":"aggregate","section":"hypotheses","limit":5}}
```

清单从当前 scope 内登记元数据与已核验观察引用产生，分别提示认证强制、第二因素、重试窗口、令牌一次性/过期失效、主体/租户边界、金额和时间边界、状态授权、幂等、导航/服务端目的地、解析器/上传和公开敏感数据属性。条目标明来源为声明、观察只表示曾捕获；缺少策略、账号、fixture、消费点、独立控制或状态读回时保留具体上下文缺口。

属性清单不是 candidate、obligation、finding 或完成指标。一个业务族或输入的已确认判定不能自动完成其他属性。公开且无输入操作仍需独立的敏感字段分类和适用证明通道，不会因正常公开响应就记安全。条目不包含已知靶场答案、payload、凭据、原始输入值或可执行目标请求。
