## Hard Stop Contract

`plan.finalize` accepts exactly the current checkpoint, `reason:completed`, an actual bounded explanation and reviewer, plus project identity. Extra force/override/host-event assertions are rejected. `blocked`, `budget_exhausted`, `user_stop` and `authorization_boundary` are not model-callable finalization exits.

One shared predicate governs readiness, stop receipts and final reporting:

1. The registered operation inventory is nonempty.
2. Current evaluated completion is complete.
3. Ready, review, blocked and unresolved counts are all zero.
4. The latest checkpoint matches the actual current snapshot.
5. Two current, complete, valid and evidence-bound frontier rounds cover discovery, all 12 family boundaries and page/function scope.
6. The latest checkpoint itself contains the complete valid frontier; blocked declarations and an unreviewed newer checkpoint cannot borrow old completion.

The frontier rounds are source-bound analyst scope attestations, not two independent experiments or an oracle for all unknown vulnerabilities. Their references and saved material hashes are revalidated. Request counts, elapsed time, finding counts, repeated checkpoints, context pressure and low yield are never exhaustion proof.

Continuation contract v2 adds `stop_policy:exhaustion_only`, `stop_policy_version:1`, `automatic_stop_allowed` and `legacy_finalization_ignored`. Stop flags are strict booleans, counts are typed integers, and compact rendering/recovery preserves the controls independently of large lists.

Independent adversarial replay found two additional ways to manufacture a zero queue: declare untested obligations `not_applicable` using one ordinary normal capture, or remove an unfinished security family. Both are now review work rather than automatic closure. `applicability_review_total` tracks source-bound but unverified exclusions; `scope_reduction_review_total` tracks untested deleted/omitted concrete family/input/branch and principal/fixture boundaries. Administrative review cannot dismiss them. Restore the actual authorized boundary and use an accepted typed experiment. A later consumer label cannot retroactively rewrite an old family. Scope-declaration metadata does not alter obligation identity, and absent zero-value derived counters do not unnecessarily invalidate genuinely closed legacy snapshots.

Final integration found caller-only blocked obligations could hide actually ready/setup/review work from the new host guard. Raw blocked declarations are now preserved while actual scope, identity, fixture, browser, material and write prerequisites are recomputed. Otherwise feasible items become `blocker_reconciliation_required` offline reopen work, never implicit execution approval. Administrative blocked text follows the same rule. Complete failed read-only browser material remains reviewable but is not successful page coverage; actual blocked requests, missing/changed material and uncertain writes stay blocked. Weaker legacy reviewed receipts are rechecked against the current real gates, not trusted merely because their original source hash still matches.

An exact-query scope also exposed a compatibility gap: registration stores a query-free operation locator, so checking that locator alone incorrectly hid feasible offline binding work as blocked. The queue now retains `scope_binding_review_required` source preparation and an ID-only `surface.inspect` handoff. A caller must provide the current intended full URL from authorized sources and independently preflight it; no query value is published, copied from a scope rule or automatically attached to a request. Required browser work remains prepare/invoke false. Actual identity, fixture, mutation, path/exclusion and blocked-page prerequisites remain blocked; qualified existing evidence still supports offline review.

An additional normal-entry local regression showed a dynamic JavaScript clue could be dismissed with an arbitrary reason, reducing unresolved candidates from one to zero and allowing two unrelated baseline-bound frontier declarations to finalize. Ordinary and legacy dismissals now remain actionable discovery review. Only a current engine-revalidated concrete URL outside declared scope (not a caller-added exclude), or an exact ordinary operation hint already covered by all current typed obligations including security work, can close that review. Dynamic/private locators, scanner findings and a baseline alone cannot qualify. Source context is private, imported closure receipts are stripped, and source/scope/evidence changes reopen review without rewriting the original disposition. Rejected import wrappers also obtain distinct nested-source identities; exact old hints retain their original ID/history while previously omitted siblings are recovered instead of colliding.

Candidate identity additionally distinguishes actual HTTP media/profile, protocol, GraphQL operation name, input/schema and declaration boundaries in both direct and wrapped hints. Identical source locations no longer collapse JSON/XML siblings. Canonical type-strict legacy matching and source-container-preserving merges retain old IDs/history only for the exact original definition, including repeated wrapper/direct import conversions. Lossy query-free locators cannot prove an authorized query-bound URL out of scope: exclusion proof uses a wider query-free path comparison without changing actual request authorization.

Old partial receipts remain unchanged in SQLite but cannot end current continuation or authorize a new final report. A genuinely completed legacy receipt must pass the new actual predicate and receipt validation. Checkpoint/snapshot changes still invalidate previous authority. No migration rewrites old evidence or manufactures host facts.

An actual explicit user pause/stop or actual host interruption preserves checkpoint/draft and exact resume prerequisites when execution permits. It is not a finalization event. No uncertain write is replayed and no authorization boundary is expanded to escape the gate. Per-call deadlines remain safety controls, not invented assessment budgets.

## Host and Report Integration

The optional penetration-mode toggle remains replayable and session-scoped. A separate optional `systemPrompt` section provides the exhaustion guard regardless of that toggle and without requiring command/projection services. Core tools still load when optional services are absent. The Python gate does not depend on any UI state.

Additional public SDK verification found the supported rc.3 `agent/turn-stopping` serial event (`dsh-agent/README.zh.md:67`, public `runtime-types.d.ts:387`). The host awaits listeners and rereads fresh steering before closing the otherwise-completed branch. `src/host-continuation.mjs` binds actual tool execution agents and admitted current user intent, audits only their active project IDs using fixed-config offline `plan.audit`, and calls public `Agent.steer(createUserMessage(...))` with plugin-owned source for remaining work/frontier/finalization. It uses neither `followup` nor `inject` as a fake veto.

The hook does not create authorization, scan historical workspaces, retract already emitted text or steer after a genuine turn/plugin abort. New admitted user intent fences old bindings, report-only inspection does not start testing, and blocked-only work remains unfinished with an offline checkpoint rather than repeated target traffic. Missing public host context is diagnosed while tools and the engine gate remain available. An audit failure is not an exhaustion proof. This supported same-turn seam still does not guarantee unbounded platform execution or override actual host termination. The public session `max-tokens` label records a step output cap even when a plugin continued the turn; it is not a measured overall budget.

The real installed SDK/Cordis serial dispatcher, Python engine and fresh loopback counters validate offline host integration using an Agent fixture, including caller-blocked ready/setup work and genuine missing POST permission/fixture. The installed public `dsh-agent` provides registry/events, not a concrete Agent constructor; `dsh-agent-loop` is absent. No desktop/live driver or LLM was launched, so its closing-to-next-step deployment path is not claimed tested.

Failed scenarios are recognized by their actual `SC-` run handle, not only HTTP/tool `RUN-` handles. If a submitted bridge call times out or cannot deliver a trustworthy outcome, a bridge-owned symbol retains the unfinished binding even without a returned run ID. JSON backend assertions cannot mint this marker. A first real failed scenario and a first real bridge timeout each use one fresh read-only loopback GET; subsequent guard audit/steering sends zero new target requests. Actual cancellation and new admitted intent still take precedence.

`report.build` defaults to draft. A final build requires the current strict completed receipt, matching snapshot/checkpoint/receipt identifiers, complete coverage, integer-zero remaining counts and consistent stop flags before preparing materials. The same sources are evaluated again after preparation, before publication. Partial/inconsistent receipts are rejected rather than exported as final-partial. Chinese report, JSON summary and manifest retain the same stage, continuation and stop basis. Protected originals and previous report batches are not overwritten.

## Additional Reproduced Security Fixes

- Shared project publication: ordinary surface registration/list/inspection, status method paths, preflight metadata and caller-selected scenario labels/errors could still echo known session credentials outside the browser-specific projector. All project results and errors now share private-context publication. Exact action-schema controls survive secret collisions, while caller-selected IDs, arbitrary business fields, encoded paths and short numeric aliases remain content. Generated local handle recovery requires private mint provenance and the actual entity/function. Required context is checked before execution; offline mutations may roll back with unsafe publication, but dispatched runs/evidence never roll back merely because output projection fails. Recovery references are tied to the invocation's actual claim/idempotent run, never another concurrent run, and require inspect/no-replay.
- Nested encoding and control order: six/ten-level percent encoding could preserve a reversibly encoded credential in direct candidate/browser APIs and report files. The shared redactor now checks bounded decoding, omits protected or still-unresolved encoded content and refuses to derive manual request templates from an omitted locator. Original source/evidence bytes remain unchanged; ordinary nonce and stable benign encoded paths remain supported. Privacy flags are applied after all caller fields, so a later `requestable:true` or binding false cannot reenable a redacted locator.
- Disk and reproduction boundaries: short PIN/alphanumeric values embedded in URL/title/body text, JSON keys, integer/float/leading-zero aliases and target-declared hex strings are content, not opaque controller fields. Text/XML/form/multipart exports use the same strict private registry and recompute HTTP Content-Length; protected or ambiguous framing becomes unavailable instead of a falsely executable template. Report summary publication distinguishes actual ledger counts/handles/material bytes from caller source fields, restores prepared placeholders and rebuilds curl/sqlmap arguments only from bound safe files and evidence order. Caller-selected UUID-shaped IDs and arbitrary source numbers are not restored. Original private keys are removed before any key redaction can disguise `body` or `headers`. Missing legacy fill context yields metadata-only reports with no request/body files or commands, while preserving unfinished continuation.
- Unknown access policy: an existing observation from another actor used to call the positive authorization predicate during queue projection, poisoning actor registration, operation updates, status, inspection and planning. Unknown policy now retains `declared_access_policy` and offline review instead of inferring an allowed identity from a successful response.
- Structured responses: duplicate object keys, nonfinite/overflow numbers, isolated surrogates, invalid UTF-8 and excessive nesting cannot satisfy identity or JSON-based evidence predicates. Parse errors must not be caught as an absent negative-control value.
- JSON state semantics: recursive literal comparison distinguishes booleans from numbers in fresh and historical baseline, semantic/state, unchanged-input, scenario and readback assertions. Finite numeric `1/1.0` equivalence and real zero remain supported. Nested `ok/status` containers and ACK-only string arrays are not concrete business-state readback; named business booleans and real domain states remain valid. Boolean JSON values cannot impersonate string/numeric resource IDs. Malformed disposition status/reason cannot poison project planning; old malformed text remains private history with a generated offline repair diagnostic.
- Authorization: `HTTP 200` with `ok:false`, a boolean or a generic denial is not protected data. Both initial evaluation and historical revalidation require actual successful business data; meaningful finite zero values remain supported.
- Localized business evidence: ASCII-only control normalization erased Chinese text, allowing `data:"\u65e0\u6743\u9650"` to confirm authorization or denial/ACK strings to refute an input hypothesis and assert readback/state transitions. Unicode-preserving normalization and bounded explicit English/Chinese denial/ACK matching now serve fresh and historical authorization, semantic-negative, state and reconciliation checks. Meaningful non-ASCII business text, named booleans, real zero, valid large integers and actual domain states are retained; Unicode is not globally rejected.
- Negative authorization and control flags: an HTTP 401/403 still carrying selected protected business data cannot automatically refute access or ownership. Fresh evaluation leaves the obligation open and legacy weak negatives reopen without changing their original history; no new HTTP-403 machine-confirmation profile is invented. Complete plain Forbidden/metadata-only denials remain supported, and malformed structured data is not swallowed as a missing field. Finite generic signal selectors such as `ok/success/allowed` cannot establish business sensitivity or state changes; genuine `/data` booleans and permitted domain status/code values remain supported.
- Browser publication: known credentials and discovered credential-bearing browser observations are removed from public metadata, including subsequent page/run/plan/report views and sensitive numeric fields. Real native action results do not retain `fill.value`, so fill secrets are learned from the caller input and preserved in integrity-bound private redaction context. Missing/changed required context fails closed; old unknown context yields safe metadata and an unavailable marker. Private digested runtime artifacts and exact proof bindings remain intact. Sanitized secret locators are explicitly nonrequestable; a nonce-bearing ordinary test URL is not blindly stripped.
- Low-entropy integrity context: new session generations and browser fill contexts contain private CSPRNG nonces, never passed as target headers or runner input. Public pure credential/context hashes are omitted instead of acting as a two-digit PIN or six-digit OTP dictionary oracle. Same-generation renewal preserves private context, legacy no-nonce verification stays compatible, and generated enum/counter fields are not reencoded when a secret happens to match a code word. Material SHA-256 remains integrity metadata, not a claim of credential encryption.
- Browser interruptions: runtime dispatch has an owned persisted execution record. Timeout or invalid output retains an uncertain run reference and recovery instructions; a closed client process does not prove that a write did not happen.
- Legacy XSS: an inferred HTML/XSS obligation without an explicit family cannot close from three HTTP numeric controls. It requires current explicit XSS planning and actual qualified runtime; old weak decisions reopen without being deleted.
- Actor self-state: header/cookie declarations and undeclared business headers cannot hide a foreign resource in a fixture-free write. Shared preflight/scenario and historical evidence checks enforce the same rule while preserving normal management headers and verified credentials.
- Windows report publication: a reproduced transient `WinError 5` staging lock receives a short, bounded atomic-rename retry only for the validated newly owned directory/destination. Other failures propagate, existing reports are never replaced, and failure never becomes success.
- Collection budgets: JSON breadth is checked before building a huge descriptor map. The development SDK's pinned Zod 4.4.3 had a high-severity constrained-collection memory exhaustion advisory; a root-only override locks Zod 4.6.6 while keeping the SDK version and single-peer-instance contract unchanged. A finite 10,001-item regression verifies early length rejection with zero item transformations.
- MCP argument validation: an out-of-range huge integer timeout is rejected by the range gate before float finiteness conversion, without a connection or an unwrapped overflow exception. Valid large JSON integers in evidence are not globally rejected as a workaround.
- MCP deadline reads: the Linux watchdog can turn a deadline interruption into clean socket EOF. A full stable WSL run exposed `mcp_protocol` instead of timeout and an incorrect complete-EOF label. The shared reader now records actual bytes, rechecks the original deadline immediately after the blocking read and only then classifies EOF. Four deterministic controls preserve real early EOF/short-body behavior and make late EOF/UTF-8/JSON partial reads timeout without extending the handshake budget or increasing test sleeps.
