# 0.6.1 Penetration Mode RPC Envelope Fix

## Symptom

Clicking the penetration-mode button in the DSH Web UI showed
`切换失败：命令未成功执行` and the mode never changed.

## Root Cause

`ctx.remote.commands.execute()` returns the DSH command RPC envelope:

```text
{ ok: true, value: { commandId, result: { kind: "success" | "error", text } } }
```

`src/client.js` read `result.value.kind` and `result.value.text`, so every
status read failed even though the host command had executed successfully.
The failure happened on the initial `/penetration status` read, before the
button could issue `/penetration` or `/penetration off`.

The session log confirmed the server side was healthy: `command/run` and
`command/done` events were appended with `kind: "success"` and
`text: "Penetration mode off."`.

## Fix

Unwrap the nested command result while keeping the old flat projection as a
compatibility fallback:

```js
const value = result.value?.result ?? result.value;
if (value?.kind !== 'success') throw new Error(value?.text ?? '命令未成功执行');
return value;
```

`tests/client.test.mjs` now uses the real `{ commandId, result }` envelope in
its default host mock and covers the nested result path.

## Validation

- `node --test tests/client.test.mjs`: 18 passed.
- `npm test`: 68 passed.
- Live DSH client HMR served the updated `awa-ddd/client.js` with the fix and
  published a new client bundle revision.
