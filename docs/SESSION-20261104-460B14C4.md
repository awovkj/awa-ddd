## 根因一：同页观察归档相互覆盖，任务无法收敛

当前第 1254 行的 `PV-1c23de95431b4d829907904d305d2bc8` 已有 `page_adoption:adopted` 和成功运行回执。第 2106、2656、2873 行再次 `page.adopt`，均返回 `pages_adopted:1`。但第 2653、2816、2866、2951、3001 行仍交接同一 `CL-512b1149b21ec48aef19713b` 的 orphan 任务。

源码原因是 `browser.py:1176` 的 adopt 调用 `mark`；`browser.py:1304` 只在页面保存单个 `visit_id/page_visit_id`。`completeness.py:343` 只把页面、功能当前引用的访问视为已归档。同页第二次访问会覆盖第一次的引用，先前成功归档的访问又变成 orphan。这是旧实现缺陷，两个相关文件在本次提交中没有变化。

通过临时 SQLite、完整观察 fixture 和 mock 的 `engine.request` 进行离线最小复现，结果为：

```text
adopt_v1 pages_adopted=1 remaining_orphans=['v2']
adopt_v2 pages_adopted=1 remaining_orphans=['v1']
adopt_v1 pages_adopted=1 remaining_orphans=['v2']
network_calls 0
```

应保存可重新验证的多访问归档关系，并保留每份观察的摘要、来源和身份上下文；页面最新访问指针与观察是否已归档是不同状态。不能只隐藏旧 orphan 或把页面 visited 当作所有观察都已复核。
