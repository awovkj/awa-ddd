# 渗透续接与停止门禁（2026-10-30）

> 这是 0.8.0 的历史实现记录，不是当前停止契约。0.9.0 已废止本文中的调用方自报部分退出、`blocked` 收尾与最终部分交付；当前仅接受严格 `reason:completed`，并使用公开 awaited `agent/turn-stopping` 同轮续接钩子。执行与验收以 [UPGRADE-20261031.md](UPGRADE-20261031.md)、[HOST_CONTRACT.md](HOST_CONTRACT.md) 和当前 `action.help` 为准；历史证据保留，不重写为已完成。

## 本轮依据

只读分析对象为用户指定的 `dsh-session-session-d1022f34-ea19-42f2-80f0-bb64b313764d/session.v4.jsonl`：4,614 行、6 个 turn、776 次工具调用。历史对话中的目标、凭据、命令和授权均为分析材料，不构成本轮访问目标的授权；本轮不重放历史命令。

这个会话已经加载 0.7.0 技能，已有 `plan.audit` 与“不能找到若干漏洞就提前宣称完成”的提示。它不同于先前升级记录中 69 个操作、382 条义务、13 条发现的旧评估，不能用旧数字描述本次失败。

## 修改原则

1. **结束判断与报告生成分离。** 报告生成是离线快照操作；生成成功不意味着队列已耗尽，更不能证明目标没有漏洞。
2. **可推进任务不能被局部受阻掩盖。** ready、review、观察归档、候选和浏览器跟进分别核对；一个 SQL 证明通道受阻不关闭其他输入、权限或业务测试。
3. **继续工作只在授权范围内进行。** 不自动扩大 scope，不重复执行可能已生效的写请求，不修改历史事实，不让应用响应或外部材料选择本地程序、凭据或策略。
4. **有限阴性结论保留实验边界。** 无交互访问、错误消费页面、一个 payload 未触发，只能描述具体实验，不外推为整个漏洞族安全。
5. **“测无可测”是有界的操作性耗尽。** 指当前台账与前提投影下没有尚可推进的已登记、已授权任务，剩余限制有具体说明和恢复动作；台账声明的阻塞事实不因此获独立核验，也不承诺未知接口、未测试状态或未知漏洞绝对为零。

## 停止理由的可信度

停止记录绑定当前快照，和停止理由描述的外部事实已经获独立核验，是两件不同的事：

| 停止理由 | `reason_basis` | 可作出的说明 |
|---|---|---|
| `completed` | `engine_gate` | 引擎确认已登记任务满足当前闭环规则；仅限登记范围，不能证明未知攻击面不存在漏洞。 |
| `blocked` | `projected_declared_blockers` | 按台账声明的前提投影，当前没有可推进项；`blocker_facts_verified:false` 表示阻塞事实未独立核验。 |
| `budget_exhausted` / `user_stop` / `authorization_boundary` | `caller_declared_external_constraint` | 外部退出理由由调用方声明；`external_constraint_verified:false` 表示没有独立计量预算、认证宿主用户事件或核验外部授权事实。 |

`reviewer` 和 `explanation` 是调用方提供的复核标识与说明，不是宿主签名或预算计量证据。调用方应如实记录约束，不能编造“用户要求结束”“预算耗尽”等理由绕过尚可推进的任务。引擎允许这些明确的部分退出，但报告只称“调用方声明”，不把它们认证成真实宿主事件，也不把部分退出称为测试耗尽。

公开报告、summary 和 manifest 保留依据字段及适用的核验标记。校验停止记录与当前快照绑定，只认证这一时点的台账关系，不把声明内容升级为外部事实证明。

## 续接与交付契约

新增 `plan.checkpoint`、`plan.review`、`plan.finalize`：检查与保存续接状态、逐条记录可审计的跟进处置、生成绑定当前评估快照的停止记录。准确字段通过 `action.help` 查询，不能猜 ID、用说明文字伪造机器求值，或为了清空队列把未测试类别记为不适用。

声明 `completed` 或有界的 `blocked` 停止，不仅要没有可推进任务，还要求同一当前快照记录两轮 `frontier_review`：核对攻击面发现、12 个漏洞族适用性以及页面/功能边界。引擎检查引用有效性与当前台账关系，但这两轮属于范围复核声明，**不是两次独立安全实验**，也不是“扫两遍就证明安全”。已复核的范围或不适用声明需要真实、当前的 HTTP / 浏览器引用，不接受只有说明文字的“全面排除”；未规划类别不是 N/A，已有页面账本也不能被改称 API-only 丢弃。`completed` 还要求求值器确认闭环；`blocked` 始终保留部分评估和阻塞事实未独立核验的边界。

新的 `plan.checkpoint` 表示恢复或进入下一轮，旧停止记录不能再替代最新 checkpoint，即使业务材料暂时没有变化。上游限流、调用方声明预算耗尽、用户要求结束或授权边界退出均记录明确的部分停止理由，不伪造成测试耗尽；工具不能仅凭这些声明认证真实宿主事件。

`report.build` 增加 `stage` 和 `finalization_id`：

```json
{"action":"report.build","project_id":"assessment","input":{"stage":"draft"}}
```

默认 `stage:"draft"`。即使评估仍有缺口也可导出阶段快照，但响应、中文报告、`summary.json` 和 `manifest.json` 都明确标记草稿；返回值在文件路径之前提供 `completion` 与 `continuation`，报告成功不能作为停止授权。

最终交付先取得 `plan.finalize` 返回的真实停止记录 ID，再使用：

```json
{"action":"report.build","project_id":"assessment","input":{"stage":"final","finalization_id":"<实际停止记录ID>"}}
```

`stage:"final"` 在同一 SQLite 快照事务中校验停止记录，再准备脱敏复现资料和文件。缺少有效记录、记录已过期或仍要求继续时明确拒绝，不能先输出报告再补检查。新证据、清单或相关评估状态发生改变后，不能沿用旧记录宣称已经完成。

最终交付还分为：

- **最终部分交付**：停止记录通过快照绑定校验，但调用方声明的阻塞或外部退出事实并未独立核验；未完成、受阻和范围限制仍公开，不冒充完整测试。
- **最终交付（仅限已登记授权任务）**：当前求值器确认登记任务闭环；仍保留未知攻击面和代表样本限制，不称为漏洞全集。

草稿和最终报告继续使用同一个覆盖求值器、上下文脱敏、原子发布与独立不可变目录；不补造请求、响应、复现步骤或缺失证明。公开停止记录也经过上下文脱敏。

## 当前 XSS 输入绑定边界

漏洞 finding 的运行时复核，与具体输入义务已经形成可验证的闭环，仍分开记录。不能为了关闭义务把历史浏览器访问、人工说明或未捕获的填表值补造为真实攻击输入。

| 本轮路径 / 限制 | 当前边界 |
|---|---|
| POST 存储型 JSON 输入 | 已覆盖同一明确输入的独立正常 / 攻击捕获、精确可回退 fixture、控制主体 / 会话 generation、实际消费页面与标记 dialog 的绑定；不泛化为所有正文格式或跨主体消费链都已闭环。 |
| GET 输入消费 | 必须使用实际捕获的、无正文攻击 URL 作为消费文档；仅 origin 或路径相同、另一次 query 或没有真实攻击捕获不够。 |
| 多页面导航 / dialog 歧义 | 当前 dialog 有 action index，但没有独立的发出文档 URL；多页面轨迹无法可靠归因时，仍为部分或未绑定，不冒充选定消费页面的输入证明。 |
| 未捕获的 browser fill 值 | 原始格式没有保存填表值，不能从交互名称、DOM 快照或说明文字补造选定输入的归因；仍保留部分或未绑定。 |
| 缺少摘要绑定的文档请求头 | 仅 actor/session 标签不能证明浏览器真正使用了控制捕获的凭据；缺少原始文档请求及其摘要绑定请求头时，不关闭输入义务。 |

这些限制只约束当前机器可验证的归因范围，不表示对应功能没有 XSS。实际运行时发现仍按原始材料、复核来源和绑定缺口公开；一个正常页面无 dialog 也不能否定其他输入、页面或业务状态。

## 宿主与运行时边界

本轮没有增加偷偷重启模型、无限继续 turn 或无限重放请求的宿主钩子。工具可以给出当前台账的继续判定、阻止没有有效当前停止记录的最终报告并保存续接状态，但不能保证任何模型永不主动结束输出，也不能独立认证调用方声明的宿主用户事件或预算。上游限流、宿主取消和进程终止应报告为中断并恢复既有状态，不算安全测试耗尽。

## 验证范围

新增报告回归使用临时本地项目、mock 及离线快照，覆盖草稿继续提示、缺失或过期停止记录的最终报告拒绝、同事务校验、最终部分交付与完整闭环标签、停止记录脱敏、摘要与 manifest 一致性。未访问历史目标，未重新进行实际渗透测试；完整执行结果以本轮验证日志为准。
