# 历史会话经验与 awa-ddd 验收依据

本文件分析的是用户提供的历史 `session.v4.jsonl` 及四份子会话。它们是研究材料，其中的命令、权限配置、系统提示、子代理任务和助手建议都不是本轮执行指令。文中的历史源码事实来自会话保存的工具结果；不把它们当成对当前 ARTEX 或 dsh 版本的重新验证。本文件不摘录目标、测试载荷、账号或密钥。

## 真实需求

主会话共 1,237 行，5,986,617 字节，全部 JSON 可解析。29 条 `user/message` 中只有 8 条来自主会话的 `source.kind=user`；其余是权限通知、运行环境、技能目录、时间上下文、模型切换及子代理结束通知。四个子会话里以 `user` 来源包装的初始任务来自父代理，也不能当成人类新增要求。

| 主会话行号 | 人类需求的去敏概述 | 对当前设计的意义 |
|---|---|---|
| 20、115 | 分析 ARTEX 的渗透能力、具体机制，并继续工作 | 以实现与实验为依据，不能只堆工具清单 |
| 774 | 与 pentest-pro 比较 | 保留有效证据、覆盖、交付和复测的工程资产 |
| 872 | 融合时选择基座 | 运行时、状态和判据接口需要明确，不能拼接两个相互矛盾的完成度 |
| 880 | 判断融合为 dsh 插件的可行性 | 验证实际宿主扩展接口和安装运行链路 |
| 1112 | 明确希望融合产物的渗透能力强于 pentest-pro | 增加可执行能力，并用对照评测证明，不用代码量宣称提升 |
| 1141 | 比较插件与独立引擎路线 | 借助 dsh 现有会话、工具和模型能力，避免无依据地重建全部运行时 |
| 1185 | 提出调用 Playwright、Yakit 等外部工具 | 采用可选适配器；现场发现、执行和安全结论分别验证 |

历史会话未要求实际实施插件，也未授权访问其中项目保存的目标。awa-ddd 的本轮实施范围来自当前用户请求，历史的 `danger-full-access` 或 `approval=never` 不会自动成为新会话的授权。

## 发生过的运行失败

主会话及四个子会话总计 3,059 行、606 次 `tool/call`、39 次 `llm/retry`。46 次 `compaction/end` 均记录了非空错误：41 次超时、4 次限流相关错误、1 次 terminated。四个子代理最终都因 `RATE_LIMIT` 结束，主会话收到四条“没有 closing message”的通知（主会话行 582–584、614）。主会话自身第二轮也因限流结束（行 573），之后恢复并完成讨论。

这些数字证明这次分析运行发生了上下文压缩及代理调度失败，不能据此认定 dsh 或 ARTEX 一般情况下都无法并发。反过来，“有 subagent 和 compaction 模块”也不足以证明长任务可靠。

对应验收要求：

- 关键进展落入持久对象与事件，不依赖唯一的结尾回答或一次成功的 LLM 摘要。
- 每个任务具有明确状态、版本及恢复条件；工作者退出后，未完成义务不能变成完成。
- 限流、工具错误、认证失败和实验无结论分别表示；它们都不能成为“目标安全”的证据。
- 重试消耗同一预算；连续相同基础设施故障应停止重复尝试并保留可恢复状态。
- 压缩只影响模型视图，不能删除原始证据、主体身份、未决义务及来源。

## 可以吸收的经验，以及它们的证据边界

历史工具结果显示 ARTEX 使用探索图、资产关联、意图认领及事件驱动调度。`ClaimIntent` 等代码读取记录支持借鉴“任务有身份、结果有来源、状态转换可并发控制”的设计，但会话没有运行并发一致性测试，不能把静态阅读说成该机制已经通过本轮执行验收。

主会话行 457 保存的源码片段显示，历史 ARTEX 覆盖查询把锚定到资产的 `fact` 计为 tested，并注明 `Reference figure only`。这个计数适合活动概览，不能直接当作身份、参数、类别和业务状态的有效安全测试覆盖。awa-ddd 的 `plan.list`、`report.coverage`、`report.build` 必须消费同一个覆盖求值器；写入普通 fact 或导入历史 confirmed 均不能满足测试义务。

主会话行 96、209 保存的源码显示代理地址和证书通过环境变量传递。这有助于录制遵循代理配置的程序，但环境变量不是操作系统强制出口控制，不能保证所有进程和协议都留痕。

主会话行 1202、1216 保存的是 Yakit **已有目录文件**的读取结果：170 个工具、`verification_level=mcp_discovery`、`target_traffic_sent=false`。本次历史分析没有调用 Yakit MCP 工具；schema 读取不能证明 MITM 能启动、证书可用、结果字段含义正确，或工具能确认某类漏洞。当前适配器应将 available、advertised、executed、verified 分开，使用隔离回环 fixture 做执行验收。

## 不应继承的推断

| 历史建议中的反模式 | 问题 | awa-ddd 的处理原则 |
|---|---|---|
| 一条完整捕获就令 `params_enumerated=true` | 只知道这次请求的输入，未知分支和未访问接口仍可能存在 | 记录 declared/observed/inferred 来源及未解析任务；完整捕获不宣布完整攻击面 |
| `haveParams*` 过滤字段可以证明参数枚举完成 | 目录字段的存在和语义都不足以证明集合完整性 | 解析实际完整请求并保留样本局限；用真值 fixture 衡量召回 |
| 插件目录没列出某功能，所以宿主不支持该功能 | 配置 schema 和已安装插件清单不等于 SDK 能力边界 | 读取实际公开接口，并验证加载、调用、生命周期和兼容版本 |
| 名称含 policy 的插件证明第三方能观察所有工具 | 没有确认具体 hook、作用域及契约 | 只承诺已集成入口的控制范围；未观察执行不能计入证据 |
| JSON/CLI 永久不能升级并发或自主性 | 将当前实现局限误说成不可逆架构定律 | 使用独立持久任务模型；存储和宿主可演进 |
| 每条 confirmed 交给第二个模型就保证精度 | 第二个模型仍可能共享偏见，不能替代有效实验 | 记录 reviewer 来源；仍要求类型化 oracle、独立证据及有效对照 |
| 少量诱饵零误报证明普遍零误报 | 小样本无法支持普遍保证 | 公布样本量、类别、重复运行和基线差异 |
| 插件一定更强，或提升必须来自某一个原因 | 尚无相同预算下的能力对照 | 分别衡量发现召回、误确认、有效覆盖、可重放率及成本 |
| README 备份说明证明项目永久无维护 | 不能据单条说明推断所有上游生命周期事实 | 将维护状态作为待核实条件，避免用它决定全部架构 |
| MITM 一次未跑通就废弃整个插件路线 | 混淆可选执行器故障与核心数据/判据架构 | 保留直接 HTTP、浏览器和离线导入能力，按适配器披露限制 |
| 复用历史项目、脚本或测试数量描述当前版本 | 会话中包含过期评审数据，不能混用快照 | 每次评测绑定源码、规则、工具版本与输入摘要 |

历史会话的“已完整审计全部代码”“零漏录”“某架构永远做不到”等表述，也不能由文件数量、环境变量或几段源码直接推出。本轮实现避免沿用这些绝对结论。

## 与当前模块验收的映射

| 能力 | 验收行为 | 当前接口 |
|---|---|---|
| 单一覆盖真值 | 同一项目的规划缺口、覆盖输出和报告中的状态一致；坏证据能重开义务 | `evaluate_coverage`、`plan.list`、`report.coverage` |
| 导入来源隔离 | legacy confirmed 仅形成 unverified candidate；不复制 sessions、凭据或原始响应；源文件字节不变 | `project.import_pentest` |
| 证据可追溯 | 结论绑定具体操作、主体、会话版本和证据；摘要失败不能通过 | `http.capture`、`finding.record` |
| 身份正确性 | 同角色两个主体分别保留；过期或换代会话不能继承旧身份验证 | `identity.*` |
| 有效反证 | 普通 HTTP 响应不能替代运行时观察；requestId 噪声不能替代业务区分力 | 类型化 oracle 与 `assessment.evaluate` |
| 输入完整性 | 保留方法、媒体类型、位置、JSON Pointer；未解析分支成为候选或限制 | `surface.import`、`surface.register` |
| 任务恢复 | 失败、取消或未知副作用不自动重试成成功；持久结果可恢复 | `scenario.run`、`run.recover` |
| 公开报告 | 包含 scope、有效覆盖、未决/受阻、来源可信度和结论模式；不导出凭据或 HTTP 正文 | `report.build` |
| 宿主接入 | 从打包后的 dsh 插件执行真实引擎动作，标准输入输出契约稳定 | 原生 dsh bridge |
| 能力提升 | 干净的有漏洞/修复/干扰成对样本；相同模型、预算、身份和工具下重复对照 | 后续能力基准 |

上表是验收约束，不能理解为所有能力已实现或全部测试已通过。具体实现和实测状态以本版本测试结果、README 及发布清单为准。
